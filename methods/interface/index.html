Method I

The Interface

The boundary between an agent and a human is not a UX problem. It is a sovereignty problem. Every interface decision either preserves or erodes the human's ability to understand, override, and remain in command.

The Problem of Delegation

Most agent interfaces optimize for speed and convenience. They treat the human as a consumer of outputs—someone who reviews what the machine produced and clicks "approve." The interface becomes a rubber stamp.

When the interface hides reasoning, compresses context, or defaults to automation, it doesn't just save time. It removes the human from the decision loop. The person is still nominally "in charge," but they lack the information, the framing, and the cognitive engagement to exercise real judgment.

In public services, this failure is compounded. Citizens interact with government systems they cannot exit. When an AI agent mediates benefits eligibility, case management, or regulatory compliance, the stakes of a hidden decision loop are not just inconvenience—they are due process violations.

The Method of Capacity

This artifact establishes comprehensive draft standards for implementing agent-mediated public services. Rather than treating agent experience as a design afterthought, it defines six primary standards domains that must be satisfied before an agent system touches a public workflow.

Standards domains

  • Accessibility: Agent interfaces must meet the same accessibility requirements as any public-facing service. No citizen should be excluded because the mediation layer wasn't designed for them.
  • Security & Privacy: Agent actions on citizen data must be bounded, auditable, and minimized. The system collects only what the task requires and retains only what the law mandates.
  • Transparency: Every agent decision produces a reasoning file—inputs, policy version, rule path, and intermediate steps. Citizens and oversight bodies can reconstruct any outcome.
  • Interoperability: Agent systems must speak to existing government infrastructure. Agencies publish authoritative, machine-readable policy logic with unique version identifiers.
  • User Experience: The human sets the tempo. Agents do not auto-execute in consequential workflows. Deliberate friction precedes irreversible actions.
  • Compliance & Governance: Agent authority is scoped, versioned, and revocable. No open-ended mandates.

Policy as versioned code

A core requirement: agencies must publish authoritative, machine-readable policy logic with unique version identifiers. Each agent decision includes a reasoning file linking inputs to the specific policy version applied. When policy changes, the system can identify every prior decision made under the old version—enabling targeted review rather than blanket audits.

Structured handoffs

When agents encounter uncertainty, rights-related issues, or user distress, they do not silently fail or loop. They transfer cases via a structured handoff package containing the reasoning file, all inputs, the policy version, and the complete action history. The receiving human has full context to continue—not a summary the agent wrote about its own work.

Civic grounding

The standards emphasize equity of access, public clarity about agent capabilities, preservation of human judgment for interpretation and rights determinations, and continuous review for algorithmic drift. These are not aspirational principles. They are testable requirements.
