Method II

The Interface

The boundary between an agent and a human is not a UX problem. It is a sovereignty problem. Every interface decision either preserves or erodes the human's ability to understand, override, and remain in command.

The Problem of Delegation

Most agent interfaces optimize for speed and convenience. They treat the human as a consumer of outputs—someone who reviews what the machine produced and clicks "approve." The interface becomes a rubber stamp.

When the interface hides reasoning, compresses context, or defaults to automation, it doesn't just save time. It removes the human from the decision loop. The person is still nominally "in charge," but they lack the information, the framing, and the cognitive engagement to exercise real judgment.

This is disintermediation by design. The interface looks collaborative, but the human is a passenger.

The Method of Capacity

Agent Experience (AX) design flips the default. Instead of optimizing for agent throughput, it optimizes for human comprehension. The interface is designed so that the human always has enough context to meaningfully evaluate, override, or redirect the agent's action.

Core interface principles

  • Context surfacing: The agent must expose why it is recommending an action, not just what it recommends. Reasoning must be visible at the point of decision.
  • Pace control: The human sets the tempo. Agents should not auto-execute in high-stakes contexts. There should be deliberate friction before irreversible actions.
  • Override affordance: Every agent action must have a clear, accessible mechanism for the human to say "no" or "not like that." Override should not require technical expertise.
  • State transparency: The human must always know what the agent has done, what it is doing, and what it plans to do next. No silent background operations in consequential workflows.

The MCP agent experience model

The Model Context Protocol (MCP) provides a structured layer for agent-to-human communication. Rather than treating the interface as a chat window or a dashboard, MCP defines explicit channels for context exchange—ensuring the human and the agent are operating from the same information at the same time.

This matters because the failure mode is not "the agent did the wrong thing." The failure mode is "the human didn't know enough to catch it."
