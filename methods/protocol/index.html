Method III

The Protocol

An agent that cannot refuse is not a tool. It is an uncontrolled process. Judgment routing is the discipline of defining exactly where human authority begins and machine execution ends.

The Problem of Delegation

Agentic systems are designed to complete tasks. Their value proposition is autonomy—give them a goal, and they figure out the steps. This works until the steps involve consequences the agent cannot evaluate: legal liability, ethical judgment, political sensitivity, or irreversible harm.

The standard response is "human-in-the-loop." But most human-in-the-loop implementations are theater. The human receives a notification, sees a summary the agent wrote about its own work, and clicks approve. There is no genuine decision point because the human lacks the context to disagree.

Judgment routing is not human-in-the-loop. It is the architecture that determines which decisions require a loop, what information the human needs to make that decision real, and what happens when the human says no.

The Method of Capacity

The Protocol defines a routing system for agentic decisions. Every action the agent can take is classified by consequence tier, and each tier has explicit rules for how much autonomy the agent retains.

Consequence tiers

  • Tier 0 — Reversible, low-stakes: Agent executes autonomously. Examples: formatting, summarization, data retrieval.
  • Tier 1 — Reversible, moderate-stakes: Agent executes with notification. Human can review and undo. Examples: scheduling, draft communications.
  • Tier 2 — Irreversible or high-stakes: Agent proposes, human approves. Execution is blocked until explicit authorization. Examples: financial transactions, public communications, personnel actions.
  • Tier 3 — Judgment-dependent: Agent refuses and escalates. The decision requires contextual judgment that cannot be reliably modeled. Examples: legal interpretation, ethical dilemmas, precedent-setting decisions.

Hard stops

A hard stop is not a warning. It is a structural barrier that prevents the agent from proceeding. Hard stops are triggered by:

  • Confidence below a defined threshold
  • Actions that cross consequence tier boundaries
  • Requests that conflict with explicit policy constraints
  • Novel situations that fall outside the agent's training distribution

When a hard stop fires, the agent does not retry. It surfaces the decision to a human with full context: what it was trying to do, why it stopped, what information the human needs to proceed.

Refusal as a feature

Systems that never say "I can't" are systems that have no limits. The Protocol treats refusal as a core capability, not a failure state. An agent that refuses an action it shouldn't take is working correctly. An agent that proceeds when it shouldn't is the one that's broken.
