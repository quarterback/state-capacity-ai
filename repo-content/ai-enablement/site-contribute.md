This project is most useful when it reflects real-world implementations. We need your examples, feedback, and improvements.

If you've deployed an AI Enablement Statement or used these frameworks, share your example so others can learn.

**Submit via:** GitHub pull request or email to [contact]

### Improve the Frameworks

Found a gap? Have a better way to explain something? Frameworks should evolve based on practice.

**Submit via:** GitHub issue or pull request

### Report What's Missing

Is there a use case we haven't covered? A type of AI system that doesn't fit the taxonomy?

**Submit via:** GitHub issue

## What Makes a Good Example?

The most useful examples have these characteristics:

* **Specific:** Not hypothetical—based on a real or realistic deployment
* **Complete:** Includes all sections of the Enablement Statement template
* **Honest:** Acknowledges limitations, unknowns, and tradeoffs
* **Clear:** Written in plain language for affected people, not technical documentation
* **Contextual:** Explains why this authority level and these safeguards make sense for this use case

## Contribution Guidelines

### For AI Enablement Statement Examples

1. **Use the template structure** from the frameworks page
2. **Include all required sections:** What the system does, AI's role, human authority, contestability, oversight, limitations
3. **Classify the system** using the Taxonomy (Advisory, Assistive, or Determinative)
4. **Be specific about safeguards** - "quarterly bias audit" not "regular monitoring"
5. **Include real contact methods** - even if placeholder, show format people can adapt
6. **Anonymize if needed** - you can use [State] or [Agency] if sharing real deployment details

### For Framework Improvements

* **Cite real-world cases** - what worked, what failed, what you learned
* **Stay practitioner-focused** - we're not writing academic papers
* **Keep it actionable** - "here's what to do" not just "here's the problem"
* **Maintain consistency** - follow existing tone and structure

### What We Won't Include

This project has a specific scope. We don't include:

* Examples of AI that doesn't touch decisions affecting people (chatbots, translation aids used as drafts)
* Technical implementation details (code, APIs, system architecture)
* Vendor marketing materials or product comparisons
* Academic research papers (though we may reference them)
* Anything that compromises individual privacy or security

## Submit Your Contribution

### Option 1: GitHub Pull Request (Preferred)

1. Fork the repository at [github.com/Digital-Corps-PDX/AI-enablement](https://github.com/Digital-Corps-PDX/AI-enablement)
2. Add your example to `/examples/` directory as a markdown file
3. Follow the naming convention: `agency-service-name.md`
4. Submit a pull request with a brief description

### Option 2: GitHub Issue

1. Open an issue at [github.com/Digital-Corps-PDX/AI-enablement/issues](https://github.com/Digital-Corps-PDX/AI-enablement/issues)
2. Use the "Example Submission" or "Framework Improvement" template
3. Include all relevant details

### Option 3: Email

If you're not comfortable with GitHub, email your contribution to: **[contact email]**

Include:
* Your example or suggested improvement
* Context about the use case
* Whether you want attribution or prefer to remain anonymous

## Example Contribution Template

Copy this template for submitting new examples:

```
# [Service Name] - AI Enablement Statement

**Contributor:** [Your name/organization or "Anonymous"]
**Date:** [Submission date]
**Authority Level:** [Advisory / Assistive / Determinative]

## AI Enablement Statement

**Service:** [Name of the service]
**Agency:** [Department/Agency - can use placeholder like [State] if needed]
**Last Updated:** [Date]

### What This System Does
[2-3 sentence description]

### AI's Role
[What the AI does - specific about automation vs recommendation]

### Human Decision Authority
[Where humans are in loop, who decides, override capability]

### How to Challenge a Decision
[Specific steps, contact methods, timelines]

### System Oversight
[Monitoring methods, where metrics published, error reporting]

### System Limitations
[What it cannot do, edge cases requiring human judgment]

## Context Notes
[Optional: explain why this authority level, what safeguards match the risk,
lessons learned from implementation, challenges faced]
```
