MCP Civic Standards v1.0

Model Context Protocol (MCP) Civic Extensions provide a structured framework for implementing policy-aware agent interactions in government and public service environments. These extensions ensure that AI agents can reliably interact with civic systems while maintaining transparency, accountability, and compliance with regulatory requirements.

Executive Summary

Government services increasingly interact with AI agents acting on behalf of citizens. The MCP Civic Standards extend the Model Context Protocol to support:

  • Policy-Aware Resources: Structured representation of eligibility rules, procedural requirements, and regulatory constraints
  • Transparent Determinations: Tools that produce auditable decisions with full reasoning chains
  • Accountability: Complete audit trails linking every action to policy versions and user consent
  • Human Handoff: Clear protocols for escalating to human caseworkers when needed
  • Equity: Ensuring agent-mediated paths provide the same rights as traditional channels

These standards build on the base MCP specification while adding civic-specific requirements for transparency, fairness, and regulatory compliance.

Part I: Domain Requirements Analysis

1.1 Regulatory Context

Public service systems must operate under strict regulatory frameworks including:

  • Administrative Procedure Act (APA) requirements for notice and comment
  • Due process protections under the Fifth and Fourteenth Amendments
  • Privacy regulations (Privacy Act, GDPR, CCPA)
  • Accessibility requirements (Section 508, ADA)
  • Records retention and FOIA compliance

1.2 Key Stakeholders

MCP Civic Standards must serve multiple constituencies:

  • Citizens: Require clear, accessible interactions with predictable outcomes
  • Caseworkers: Need complete context when agents escalate cases
  • Agency Administrators: Must ensure policy compliance and audit readiness
  • Oversight Bodies: Require transparency into agent decision-making
  • Agent Developers: Need clear interfaces and testing frameworks

1.3 Critical Requirements

Unlike commercial applications, civic systems require:

  • Explainability: Every decision must be reconstructible with full reasoning
  • Version Control: Policy changes must be tracked and tied to specific determinations
  • Non-Discrimination: Agents must not introduce or amplify bias
  • Human Review: Citizens must have access to human judgment for important decisions
  • Data Minimization: Collect only necessary information with proper consent

Part III: Implementation Patterns

3.1 Basic Eligibility Check

Python example showing a simple agent using MCP Civic tools:

import mcp
from datetime import datetime

async def check_snap_eligibility(client, applicant_data, consent_token):
    """
    Check SNAP eligibility using MCP Civic determination tool.
    
    Args:
        client: MCP client instance
        applicant_data: Dictionary with applicant information
        consent_token: Verified user consent
    
    Returns:
        Dictionary with determination result and reasoning
    """
    # Get the current policy version
    policy = await client.read_resource(
        "civic://benefits.gov/snap/eligibility/latest"
    )
    
    # Execute determination tool
    result = await client.call_tool(
        "determine_eligibility",
        {
            "policyVersion": policy["metadata"]["version"],
            "applicantData": applicant_data,
            "consentToken": consent_token,
            "requestingAgent": {
                "agentId": "snap-assistant-v1",
                "agentVersion": "1.2.0",
                "userIdentity": applicant_data.get("userId")
            }
        }
    )
    
    # Check if escalation is needed
    if result["escalationRequired"]:
        await escalate_to_human(result)
        return {
            "status": "escalated",
            "message": "Your case requires human review. A caseworker will contact you within 2 business days.",
            "escalationId": result["auditLog"]["determinationId"]
        }
    
    # Return determination with human-readable explanation
    return {
        "status": "complete",
        "eligible": result["determination"]["eligible"],
        "benefit": result["determination"]["estimatedBenefit"],
        "explanation": generate_explanation(result["reasoning"]),
        "nextSteps": result["nextSteps"],
        "determinationId": result["auditLog"]["determinationId"]
    }

def generate_explanation(reasoning):
    """Convert technical reasoning to plain language."""
    rules = reasoning["rulesEvaluated"]
    explanations = []
    
    for rule in rules:
        if rule["result"]:
            explanations.append(f"✓ {rule['ruleId']}: Requirements met")
        else:
            explanations.append(f"✗ {rule['ruleId']}: Requirements not met")
    
    return "\n".join(explanations)

3.2 Multi-Step Application Process

Handling complex workflows with state management:

class SnapApplicationAgent:
    """Agent for managing SNAP application workflow."""
    
    def __init__(self, mcp_client):
        self.client = mcp_client
        self.application_state = {}
    
    async def start_application(self, user_id, consent_token):
        """Initialize new SNAP application."""
        # Create application record
        self.application_state = {
            "applicationId": generate_uuid(),
            "userId": user_id,
            "status": "in_progress",
            "step": "intake",
            "startTime": datetime.utcnow().isoformat(),
            "consentToken": consent_token,
            "auditTrail": []
        }
        
        # Log application start
        await self._log_action("application_started", {
            "applicationId": self.application_state["applicationId"]
        })
        
        return {
            "applicationId": self.application_state["applicationId"],
            "message": "Application started. Let's gather some information.",
            "nextStep": "collect_household_info"
        }
    
    async def collect_household_info(self, household_data):
        """Collect and validate household information."""
        # Validate data against schema
        policy = await self.client.read_resource(
            "civic://benefits.gov/snap/eligibility/latest"
        )
        
        validation_result = await self.client.call_tool(
            "validate_data",
            {
                "schema": policy["content"]["dataSchemas"]["household"],
                "data": household_data
            }
        )
        
        if not validation_result["valid"]:
            return {
                "status": "validation_error",
                "errors": validation_result["errors"],
                "message": "Please correct the following information."
            }
        
        # Store validated data
        self.application_state["householdInfo"] = household_data
        self.application_state["step"] = "collect_income"
        
        await self._log_action("household_info_collected", {
            "fields": list(household_data.keys())
        })
        
        return {
            "status": "success",
            "nextStep": "collect_income",
            "message": "Household information saved. Now let's review your income."
        }
    
    async def submit_for_determination(self):
        """Submit complete application for eligibility determination."""
        if not self._is_complete():
            return {
                "status": "incomplete",
                "missingFields": self._get_missing_fields()
            }
        
        # Perform determination
        result = await check_snap_eligibility(
            self.client,
            self._prepare_applicant_data(),
            self.application_state["consentToken"]
        )
        
        # Update application status
        self.application_state["status"] = "determined"
        self.application_state["determination"] = result
        self.application_state["completedTime"] = datetime.utcnow().isoformat()
        
        await self._log_action("determination_completed", {
            "determinationId": result.get("determinationId"),
            "eligible": result.get("eligible")
        })
        
        return result
    
    async def _log_action(self, action, details):
        """Log action to audit trail."""
        log_entry = {
            "timestamp": datetime.utcnow().isoformat(),
            "action": action,
            "details": details
        }
        self.application_state["auditTrail"].append(log_entry)
        
        # Also log to MCP server
        await self.client.call_tool(
            "log_action",
            {
                "applicationId": self.application_state.get("applicationId"),
                "logEntry": log_entry
            }
        )
    
    def _is_complete(self):
        """Check if all required information is collected."""
        required = ["householdInfo", "incomeInfo", "resourceInfo"]
        return all(field in self.application_state for field in required)
    
    def _get_missing_fields(self):
        """Return list of missing required fields."""
        required = ["householdInfo", "incomeInfo", "resourceInfo"]
        return [field for field in required if field not in self.application_state]
    
    def _prepare_applicant_data(self):
        """Combine all collected data into applicant data structure."""
        return {
            "householdSize": self.application_state["householdInfo"]["size"],
            "grossMonthlyIncome": self.application_state["incomeInfo"]["monthly"],
            "liquidResources": self.application_state["resourceInfo"]["liquid"],
            "hasElderlyOrDisabled": self.application_state["householdInfo"]["hasElderly"],
            "state": self.application_state["householdInfo"]["state"],
            "userId": self.application_state["userId"]
        }

3.3 Human Handoff Pattern

Escalating to human caseworkers with complete context:

async def escalate_to_human(determination_result):
    """
    Create handoff package for human caseworker.
    
    Packages all agent reasoning, inputs, and context for seamless
    transition to human review.
    """
    handoff_package = {
        "handoffId": generate_uuid(),
        "timestamp": datetime.utcnow().isoformat(),
        "priority": determine_priority(determination_result),
        "reason": determine_escalation_reason(determination_result),
        
        # Complete agent context
        "agentContext": {
            "determinationId": determination_result["auditLog"]["determinationId"],
            "policyVersion": determination_result["reasoning"]["policyVersionApplied"],
            "dataProvided": determination_result["auditLog"]["inputs"]["dataProvided"],
            "rulesEvaluated": determination_result["reasoning"]["rulesEvaluated"],
            "agentRecommendation": determination_result.get("agentRecommendation")
        },
        
        # User-friendly summary for caseworker
        "summary": {
            "applicantId": determination_result["auditLog"]["actor"]["actingOnBehalfOf"]["userId"],
            "programRequested": "SNAP",
            "issuesIdentified": extract_issues(determination_result),
            "documentsNeeded": extract_missing_documents(determination_result),
            "userRequest": determination_result.get("userMessage")
        },
        
        # Action history
        "actionHistory": determination_result["auditLog"]["metadata"].get("priorActions", []),
        
        # Required caseworker actions
        "requiredActions": [
            {
                "action": "review_documentation",
                "description": "Verify income documentation",
                "priority": "high"
            },
            {
                "action": "make_determination",
                "description": "Final eligibility determination",
                "priority": "high"
            },
            {
                "action": "notify_applicant",
                "description": "Send determination notice",
                "priority": "medium"
            }
        ]
    }
    
    # Submit to caseworker queue
    await submit_to_queue(handoff_package)
    
    # Send notification to applicant
    await notify_applicant(
        determination_result["auditLog"]["actor"]["actingOnBehalfOf"]["userId"],
        {
            "message": "Your application requires human review.",
            "expectedTime": "2 business days",
            "handoffId": handoff_package["handoffId"]
        }
    )
    
    return handoff_package

def determine_priority(result):
    """Determine priority level for human review."""
    if "urgent" in result.get("flags", []):
        return "urgent"
    if "hardship" in result.get("flags", []):
        return "high"
    return "normal"

def determine_escalation_reason(result):
    """Extract primary reason for escalation."""
    if result.get("incompleteData"):
        return "incomplete_documentation"
    if result.get("conflictingData"):
        return "conflicting_information"
    if result.get("userRequestedHuman"):
        return "user_requested"
    return "policy_requires_review"

Part IV: Governance and Security Requirements

4.1 Policy Version Control

  • Every policy change receives a semantic version number (major.minor.patch)
  • Breaking changes increment major version
  • Policy documents are immutable once published
  • Historical versions must remain accessible for audit purposes
  • Version metadata includes effective dates, authority citations, and approval records

4.2 Data Governance

  • Data Minimization: Collect only information required by policy
  • Purpose Limitation: Use data only for stated determination purposes
  • Consent Management: Obtain and track explicit user consent
  • Access Controls: Role-based access with audit logging
  • Retention Schedules: Automated enforcement of retention policies
  • Right to Explanation: Users can request full reasoning for any determination

4.3 Security Controls

  • Authentication: Multi-factor authentication for sensitive operations
  • Authorization: Agents must present valid credentials and user consent
  • Encryption: TLS 1.3+ for transport, AES-256 for data at rest
  • Integrity: Cryptographic hashes for audit logs and determinations
  • Non-Repudiation: Digital signatures for critical actions
  • Rate Limiting: Prevent abuse and ensure fair access

4.4 Fairness and Bias Mitigation

  • Regular audits for disparate impact across protected classes
  • Testing with diverse scenarios and edge cases
  • Monitoring for statistical anomalies in outcomes
  • Human review of system-wide patterns
  • Transparent reporting of outcome distributions

4.5 Oversight and Accountability

  • Designated agency official responsible for MCP implementation
  • Regular compliance reviews and audits
  • Public reporting on agent usage and outcomes
  • Incident response procedures for errors or security events
  • Clear escalation paths for policy questions

Part V: Testing and Validation Framework

5.1 Unit Testing

Test individual policy rules in isolation:

  • Verify rule logic with known inputs and expected outputs
  • Test boundary conditions (income exactly at limit, etc.)
  • Validate error handling for invalid inputs
  • Confirm correct handling of missing optional data

5.2 Integration Testing

Test complete determination workflows:

  • End-to-end application processing
  • Handoff to human caseworkers
  • Audit log generation and integrity
  • Policy version transitions
  • Multi-program interactions

5.3 Compliance Testing

Verify adherence to regulatory requirements:

  • WCAG 2.1 AA accessibility compliance
  • Privacy protection mechanisms
  • Records retention enforcement
  • Due process protections
  • Non-discrimination requirements

5.4 Performance Testing

  • Response time under normal load (< 2 seconds)
  • Behavior under high load (graceful degradation)
  • Audit log write performance
  • Resource utilization monitoring

5.5 Security Testing

  • Penetration testing for vulnerabilities
  • Authentication and authorization bypass attempts
  • Input validation and injection attacks
  • Encryption verification
  • Audit log tampering resistance

5.6 User Acceptance Testing

  • Testing with actual caseworkers and applicants
  • Usability assessment for diverse populations
  • Accessibility evaluation with assistive technologies
  • Clarity of explanations and notifications
  • Handoff process effectiveness
